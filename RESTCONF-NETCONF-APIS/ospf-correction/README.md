This is a lab project I built to practice solving OSPF adjacency issues using Python, NETCONF, and Netmiko. The script identifies mismatched Hello/Dead timers and duplicate Router-IDs by comparing a live device against the interface in its subnet, whose data is stored in a JSON file. Once a mismatch is found, the script builds the necessary CLI commands and pushes them to the device to bring the OSPF neighbor relationship up.

The logic follows a hybrid automation workflow: it uses NETCONF to pull operational data (which is much easier than parsing CLI output), but goes to Netmiko to apply the actual configuration. NETCONF is great for reading state, but OSPF YANG models can be incredibly finicky across different IOS-XE versions. Using Netmiko for the "write" phase was a more reliable way to be sure that the commands were applied exactly as intended. This does make the script perhaps less scalable and vendor-agnostic.

A major part of this project was handling the constraint that Router-IDs cannot match. I wrote the logic to detect if a new device is using the same RID as its neighbor and, if so, prompt for a unique one. I also had to make the script resilient; I learned that if OSPF is down, operational data often returns as "Unknown" or empty, which are situations I had to handle gracefully in the script.

In the future, I want to expand on this by automating the verification of the OSPF state machine and exploring how to scale these normalization checks across an entire area. MTU issues can sometimes stick OSPF in the Exstart/Exchange state, so troubleshooting MTU mismatch would be another good way to build out this script. Moving from simple interface scripts to logic that understands protocol constraints like OSPF adjacency has been a great step in my automation journey.
